# 产品需求：写作作业模块

## 1. Problem

现有 `D:\AFrontend\XQL` 系统专注于随机口语训练。教师和学生只能完成“试音、抽题、资料搜集、草稿整理、录音演讲、教师评价”的口语流程，系统内没有写作作业入口。

教师需要布置写作作业，并希望：

- 学生在写作过程中不获得语法提示。
- 学生第一次提交后，系统自动标出语法错误位置。
- 系统只标位置，不告诉学生正确改法。
- 教师能控制某项写作作业是否启用该语法检测。
- 学生首次提交后有机会修改并再次提交。
- 教师能查看学生进入写作页面、离开页面以及停留/离开时长。
- 写作页面不允许复制粘贴。

## 2. Goal

在现有口语训练系统内新增一个独立的写作作业业务闭环：

```text
教师创建写作作业
-> 学生进入并写草稿
-> 学生提交初稿
-> 若教师启用检测，则只标注语法问题
-> 学生在允许次数内修改并再次提交
-> 教师查看版本、语法问题和页面行为记录
```

成功标准是：教师可以布置、发布和关闭写作作业；学生可以完成写作、提交、按规则修改；教师可以看到语法标注结果和学生停留/离开记录；写作页面普通复制粘贴被阻止。

## 3. Existing System Baseline

### Existing

- 学生注册、登录、邮箱验证码、JWT。
- 管理员创建教师账号、管理班级、启停账号。
- 教师创建班级，学生用邀请码加入。
- 教师管理题库和题目。
- 教师创建、发布、关闭口语训练任务。
- 学生按状态机完成口语训练并提交录音。
- 教师查看提交并发布五维评价。
- 已有 OpenAI-compatible AI 调用能力，用于题库导入。
- 已有 Alembic、SQLAlchemy、Pydantic、FastAPI 分层结构。

### Change

- 新增写作作业、写作提交、写作版本、语法问题、页面停留、违规事件模型。
- 新增学生写作页面、教师写作任务和提交页面。
- 前端导航增加写作入口。
- 后端新增 `/writing/*` 路由和写作服务。
- 配置中增加写作检测超时、页面心跳超时等字段。

### Keep

- 现有用户、班级、教师、学生、JWT、权限依赖。
- 现有口语训练任务、训练状态机、录音、评价功能。
- 现有 OpenAI-compatible 配置项和 `httpx` 调用模式。
- 现有 React Query、Zustand、Tailwind、React Router 结构。

## 4. Scope

本次实现范围：

- 写作作业管理。
- 学生草稿自动保存。
- 首次提交后语法标注。
- 教师按作业控制语法检测是否启用。
- 有限次修改和再次提交。
- 页面停留/离开追踪。
- 写作页面复制粘贴拦截和记录。
- 教师查看写作提交和追踪数据。

## 5. Non-Goals

本次不实现：

- 写作内容自动评分。
- 写作内容相似度/抄袭检测。
- 语法错误自动修改。
- 拼写检查和风格建议。
- 多人协作写作。
- 学生上传附件、图片或 PDF。
- 写作评论流或实时教师批注。
- 导出 Excel/PDF。
- 修改现有口语训练状态机。
- 移动端原生 App。

## 6. Actors

| Actor | 说明 |
| --- | --- |
| Student | 学生加入班级，完成写作作业 |
| Teacher | 教师创建班级和写作作业，查看提交、语法问题和行为记录 |
| Admin | 系统管理员，维护账号和班级；本模块不新增管理员专属能力 |
| External AI Provider | OpenAI-compatible Chat Completions 服务，用于只返回语法问题位置和类别 |

## 7. Functional Requirements

### FR-001 教师创建写作作业

教师可创建写作作业草稿，设置标题、写作要求、目标班级、开始时间、截止时间、最少/最多字数、语法检测策略和修改次数。

### FR-002 教师发布和关闭写作作业

教师可将草稿发布，也可将已发布任务关闭。关闭后学生不能继续提交，但已提交数据仍可查看。

### FR-003 学生可见写作任务

学生只能看到自己所在班级且已发布的写作作业，不能看到草稿作业。

### FR-004 学生创建或恢复写作提交

学生进入写作作业后，系统为每个学生每个作业创建唯一写作提交；若已存在，则恢复已有草稿和状态。

### FR-005 草稿自动保存

学生在写作页面输入时，草稿在前端本地暂存并 debounce 后保存到后端。刷新页面、重新进入时可恢复最后保存草稿。

### FR-006 写作过程中不显示语法问题

在首次提交前，以及每次修改但尚未再次提交时，前端不显示语法问题。

### FR-007 首次提交后语法标注

当教师启用 `after_submit` 策略时，学生首次提交后，后端调用语法检测服务，前端只显示问题位置、段落和固定类别提示，不显示正确改法。

### FR-008 教师控制语法检测策略

每个写作作业可设置：

- `off`：任何版本都不进行语法检测。
- `after_submit`：提交后检测，写作时不检测。

### FR-009 有限次修改和再次提交

教师设置 `revision_limit`，表示首次提交后允许的再次提交次数。学生提交版本是不可变快照，修改基于最新版本内容。

### FR-010 提交状态锁定

当学生用尽修改次数或作业截止时，系统锁定最终版本，学生不能继续编辑和提交。

### FR-011 页面停留/离开追踪

学生进入写作页面后，系统记录每次连续停留的开始、结束、心跳和离开原因。教师可查看总停留时长、总离开时长、离开次数和时间区间。

### FR-012 禁止复制粘贴

写作页面阻止普通复制、剪切、粘贴、右键菜单和拖拽文本。学生不能通过页面普通交互把外部文本粘贴进写作编辑器。

### FR-013 违规尝试记录

系统记录被拦截的复制、剪切、粘贴、右键等事件，教师可在提交详情中查看。

### FR-014 教师查看写作提交

教师可按作业查看学生列表，并查看每个学生的版本、字数、语法问题、页面停留/离开记录和违规尝试记录。

### FR-015 权限隔离

学生只能访问自己的写作提交；教师只能访问自己创建的写作作业和对应提交；非班级学生不能访问。

## 8. Constraints

- 使用现有 PostgreSQL + SQLAlchemy 2.0 + Alembic。
- 使用现有 FastAPI + Pydantic + JWT 权限体系。
- 使用现有 React 19 + Vite + TypeScript + React Router 7 + React Query 5 + Zustand + Tailwind。
- 语法检测复用现有 `OPENAI_MODEL`、`OPENAI_BASE_URL`、`OPENAI_API_KEY`。
- 不引入 Kafka、Redis、Celery、微服务或复杂 Agent 框架。
- 写作编辑器优先使用原生 `textarea`，不引入富文本编辑器。

## 9. Assumptions

### AS-001 语法检测策略只有两种

Assumption:
教师控制语法检测的策略为 `off` 和 `after_submit` 两种。

Reason:
用户明确要求“写的时候不提示，第一次提交以后提示”，没有要求草稿阶段实时提示。

Impact:
`WritingAssignment.grammar_hint_mode` 定义为二值枚举，未来再扩展为草稿实时检测会需要 migration。

### AS-002 修改机会按“再次提交次数”计算

Assumption:
`revision_limit=1` 表示首次提交后允许再提交 1 次，最终有初稿和修改稿两个版本。

Reason:
教师口语任务已有“重抽次数、重录次数”这种次数语义，沿用该语义更符合现有产品认知。

Impact:
前端显示“剩余修改次数 = revision_limit - 已提交的后续版本数”。

### AS-003 页面追踪属于行为监控，不是法证级精确定时

Assumption:
浏览器关闭、断网、设备锁屏时允许使用心跳超时估算离开时间，并标记为估算。

Reason:
纯前端事件无法保证 `beforeunload`/`pagehide` 永远成功。

Impact:
教师端展示总停留/离开时长为可靠估算，UI 需要标注 `idle_timeout` 区间。

### AS-004 禁止复制粘贴是前端强约束，不是绝对防作弊

Assumption:
普通复制粘贴、右键和拖拽必须被阻止；浏览器 DevTools、截图、OCR、系统级工具不在产品承诺内。

Reason:
浏览器安全模型无法完全禁止用户查看自己输入的内容。

Impact:
验收只覆盖页面普通交互拦截和违规记录，不验收绕过 DevTools 的极端场景。

### AS-005 语法检测只标注语法问题，不包含拼写和风格

Assumption:
检测类别围绕语法和句子结构，不加入拼写、用词风格、内容评价。

Reason:
用户说的是“语法错误检测”。

Impact:
前端类别只展示固定语法类别，不展示拼写建议和润色建议。
