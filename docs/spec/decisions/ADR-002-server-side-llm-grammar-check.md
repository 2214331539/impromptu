# ADR-002 服务端 LLM 语法检测 + 固定类别提示

## Context

系统需要自动检测语法错误，但必须：

- 写作过程中不提示。
- 首次提交后才提示。
- 只标位置，不告诉正确改法。
- 教师可控制某作业是否启用。

现有项目已经使用 OpenAI-compatible Chat Completions 做 AI 题库导入，配置项和后端调用模式已经存在。

## Decision

采用：

1. 服务端提交后调用现有 OpenAI-compatible API。
2. 文本先分段，AI 返回段内字符范围和固定类别。
3. 后端校验、clamp、去重、换算为全文偏移。
4. 用户提示语由后端固定映射，不使用 AI 返回的修改建议。
5. AI 失败不阻塞提交，`grammar_status=failed`。

## Reason

- 复用已有 AI 配置，避免新增第三方服务。
- 服务端检测保证策略由后端控制，学生不能通过前端绕过。
- 分段返回相对偏移，比全文偏移更可靠。
- 固定提示语从根本上避免“告诉学生怎么改”。
- AI 失败降级保证写作提交主流程仍可用。

## Rejected Alternatives

### 前端实时语法检测

拒绝原因：

- 与“写的时候不提示”冲突。
- 检测逻辑和 API Key 不适合暴露在前端。
- 输入过程中频繁调用 AI 成本和延迟高。

### LanguageTool 本地/独立服务

拒绝原因：

- 需要额外部署和运维。
- 现有项目没有 LanguageTool 依赖。
- 对中文写作支持不是当前明确需求。

### AI 返回正确改法，前端隐藏建议

拒绝原因：

- 后端仍保存了正确改法，数据泄露风险高。
- Prompt 或前端实现改变时可能意外展示建议。
- 不符合“只标出来不告诉怎么改”的严格语义。

## Consequences

正面：

- 语法问题只保留位置和类别。
- 后端能统一控制检测策略。
- 与现有 AI 调用模式一致。

负面：

- LLM 字符偏移可能不准，需要严格 normalization。
- AI 服务不可用时无法获得语法标注。
- 每个提交版本检测有额外延迟和成本。
